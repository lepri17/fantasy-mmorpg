# SERVER – שרת האונליין

עודכן: 2026-11-18

השרת נמצא בתיקייה `server/`. הוא כתוב ב-Python (asyncio + websockets) וקורא את אותם קובצי נתונים כמו המשחק (`client/data/*.json`).
**המצב:** השרת בנוי ועובר בדיקות. **המשחק עוד לא מתחבר אליו.** את צד הלקוח (מסך כניסה, שחקנים אחרים, מפלצות מהשרת, צ'אט וחלונות) עוד צריך לבנות.

## איך מריצים
צריך Python 3.10 ומעלה.

```
pip install -r server/requirements.txt
python -m server
```

ברירת המחדל: פורט 8765, ומסד נתונים SQLite בקובץ `server.db`. את הפקודה מריצים מהתיקייה הראשית של הריפו. אפשרויות:

| אפשרות | משתנה סביבה | ברירת מחדל |
|---|---|---|
| `--port` | `PORT` או `MMO_PORT` | 8765 |
| `--host` | `MMO_HOST` | 0.0.0.0 |
| `--db` | `DATABASE_URL` | `sqlite:///server.db` |
| `--channels` | `MMO_CHANNELS` | 3 |

- PostgreSQL: `--db postgresql://user:pass@host:5432/dbname`. צריך גם `pip install "psycopg[binary]"`.
- בדיקת חיים: `GET /health` מחזיר `OK`. ספקי ענן משתמשים בזה כדי לוודא שהשרת עובד.
- עצירה: Ctrl+C. כל הדמויות נשמרות לפני היציאה.

## ענן (N13)
- `Dockerfile` בתיקייה הראשית בונה את השרת עם הנתונים: `docker build -t mmo-server .`, ואחר כך `docker run -p 8765:8765 -e DATABASE_URL=... mmo-server`.
- בענן כדאי PostgreSQL מנוהל, כי קובץ SQLite בתוך קונטיינר נמחק בכל עדכון.
- בטלפון צריך כתובת `wss://` (WebSocket מאובטח). רוב ספקי האירוח נותנים TLS לבד, למשל Render, Fly.io או Railway. בשרת משלך אפשר לשים לפניו Caddy או nginx.
- הצעדים החיצוניים (חשבון אצל ספק, מסד נתונים, דומיין) הם של מור.

## בדיקות
```
pip install -r server/requirements-dev.txt
python -m pytest -q server/tests
ruff check --config server/ruff.toml server/
```
- 30 בדיקות. הן מכסות: חוקי המשחק, חשבונות, דמויות, תנועה, קרב, שלל, מוות, שערים, חנות, חיבור מחדש, ערוצים, צ'אט, Party, מסחר, גילדות, דו-קרב, אזור PvP, טבלת דירוג, ושני לקוחות אמיתיים דרך WebSocket.
- עם `TEST_DATABASE_URL=postgresql://...` בדיקות מסד הנתונים רצות גם על PostgreSQL. ב-CI יש לזה job בשם `server`.
- `server/tests/fixtures/godot_stats.json` נוצר ב-Godot על ידי `client/tests/stats_fixture.gd`. הבדיקה מוודאת שהחישובים ב-Python זהים ל-GDScript: HP, התקפה, הגנה, קריטי, ציוד, סטים, שדרוג מקצוע ותארים. אם משנים את החוקים בלקוח, צריך ליצור את הקובץ מחדש.

## מה השרת עושה
- **מקור האמת (N2, N12).** השרת שומר דמויות, מחשב את הנזק, בודק Cooldown, Stamina ורמה, ומגריל שלל. הלקוח רק מבקש:
  - `cast` – מתחיל תקיפה או סקיל.
  - `hit` – מדווח על מי פגע. השרת בודק שיש תקיפה פתוחה, שהמטרה בטווח, ושלא נגמרו הפגיעות של אותה תקיפה.
- **מפלצות.** שיטוט, רדיפה, רצועה (Leash), התקפה, Slam אחרי אזהרה, ירי, בוס שמתעצבן ומזמן עזרה, ומפלצות עלית. הן עוקפות עצים וסלעים.
- **הגנות (N12):**
  - בדיקת מהירות תנועה. תזוזה מהירה מדי מוחזרת אחורה עם `pos`.
  - הגבלת קצב: 40 הודעות לשנייה. אחרי הרבה הודעות פסולות החיבור נסגר.
  - הגבלת ניסיונות כניסה לכל כתובת.
  - סיסמאות שמורות עם scrypt, וטוקנים שמורים מגובבים.
- **חשבונות (N3).** הרשמה, כניסה, טוקן לכניסה אוטומטית ל-30 יום, ו-3 משבצות לדמויות. כניסה ממכשיר שני מנתקת את הראשון.
- **חיבור מחדש (N4).** אחרי ניתוק, `resume` עם הטוקן תוך 2 דקות מחזיר את הגיבור לאותו מקום, עם אותו HP.
- **ערוצים (N11).** לכל מפה 3 ערוצים, ועד 50 שחקנים בכל ערוץ.
- **צ'אט (N5).** כללי, מפה, Party, גילדה ולחישה (`@שם`). הצ'אט מסנן מילים גסות ומגביל קצב.
- **Party (N6).** עד 5 שחקנים. ה-XP מתחלק בין מי שקרוב, עם בונוס של 10% לכל חבר. השלל של חבר שייך לכל ה-Party. חלון ה-Party מקבל את ה-HP של כולם כל שנייה.
- **מסחר (N7).** הצעה, LOCK, ואז CONFIRM משני הצדדים. כל שינוי מבטל את הנעילות. לפני ההחלפה השרת בודק שוב את התיק, את הזהב ואת המקום, ושומר מיד.
- **גילדות (N8).** ייסוד מרמה 5 תמורת 1000 זהב, הזמנה, יציאה, הוצאת חבר, העברת הנהגה, וצ'אט גילדה. שם הגילדה מופיע מעל הדמות.
- **PvP (N9).** דו-קרב בהסכמה. הוא נגמר ב-1 HP ולא במוות, ונספר כניצחון. ביער יש גם אזור PvP (`pvp_zone` ב-`maps.json`). בשני המקרים הנזק בין שחקנים הוא חצי.
- **טבלת דירוג (N10).** לפי רמה, הריגות או ניצחונות בדו-קרב.
- **עדיין לא באונליין:** המרתף (מבוך), פלישת סליימי הזהב, אירועים.

## הפרוטוקול
- כל הודעה היא JSON עם `t` (הסוג).
- **לפני כניסה:** `hello`, `register`, `login`, `resume`.
- **במסך הדמויות:** `chars`, `create`, `delete`, `play`, `logout`, `top`.
- **בעולם:**
  - תנועה וקרב: `move`, `dash`, `cast`, `hit`, `pick`, `portal`, `respawn`, `channel`, `leave`.
  - פעולות של פריטים ואנשי העיר: `server/actions.py`.
  - חברתי: `server/social.py`.
- **השרת שולח:**
  - כניסה: `auth`, `chars`, `enter` (כל מה שבמפה).
  - תנועה ומצב: `snap` (מיקומים 10 פעמים בשנייה), `char` (הדמות בפורמט השמירה של המשחק, גרסה 10), `me` (HP ו-Stamina).
  - קרב: `dmg`, `die`, `revive`.
  - מפלצות: `mspawn`, `mgone`, `matk`, `mshot`, `tele`.
  - שלל: `loot`, `unloot`.
  - הודעות ואפקטים: `msg` (טקסט ליומן, באנגלית, כדי שהלקוח יתרגם), `fx`.
  - חברתי: `chat`, `party`, `trade`, `guild`, `invite`, `duel`, `top`.

## הצעד הבא: הלקוח
1. מסך כניסה (כתובת שרת, שם, סיסמה), ומסך דמויות שמקבל את הרשימה מהשרת.
2. `online.gd` – החיבור (`WebSocketPeer`), שמירת הטוקן וחיבור מחדש.
3. `online_world.gd` – מקבל `enter` ו-`snap`. מצייר שחקנים אחרים עם החלקת תנועה, ומפלצות כ"בובות" שהשרת מזיז.
4. ב-`player.gd`: בשולי `_strike` נשלחים `cast` ו-`hit`, במקום לחשב נזק. הפעולות ב-`player_base.gd` נשלחות לשרת.
5. חלונות: צ'אט, Party, מסחר, גילדה, דירוג, הזמנות ובחירת ערוץ. וגם הרשאת `INTERNET` ב-`export_presets.cfg`.
